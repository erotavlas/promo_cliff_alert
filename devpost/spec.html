Subscription Tracker with Negotiation Coach

Technical spec · draft · canonical text is devpost/spec.md

How this works

One Next.js project (TypeScript). Screens run in the browser, subscriptions are saved in the browser's localStorage, seeded negotiation results are a JSON file matched by plain code, and a tiny server (two API routes) holds the Anthropic key and makes Claude's two jobs: structure a plan description, and write a sectioned call script.

Components

Storage and subscription hook

Reads and writes the list under subtracker.v1; add, update, cancel, restore, delete.

Pricing and status logic

Current = full − discount; new = full. Needs attention at 30 days or fewer, or past. Color hue from green (90+ days) to red (0 or past).

Add / Edit form

Matching logic

lib/matching.tsprd: Negotiate screen

Equivalent, else closest, else none. Drops results where the final price is higher than the start, sorts lowest final first.

Script screen and LLM module

app/subscription/[id]/scriptlib/llm.tslib/templateScript.tsprd: Script screen

Sectioned script (Opening, If they refuse, Closing); regenerate and tweak; template fallback if the call fails.

Data

Subscription (localStorage)id, name, category, customCategory?, planText, planFeatures[], logoDomain?, contact, startDate, isContract, contractMonths?, fullPrice, discount, promoEndDate, status, cancelledAt?
Derived, not storedcurrent/new price, yearly figures, days left, color, needs attention
NegotiationResult (JSON)id, provider, category, username, planFeatures, startPrice, finalPrice

Failure modes and simplifications

  • Plan call fails → plain error, typed text kept (API assumed reachable for the demo).
  • Script call fails → template script plus note.
  • Logo not found → letter circle.
  • Simplified: localStorage instead of a database; seeded JSON instead of crowdsourcing; plain-code matching; no offline/local model; local run plus recording instead of deployment.
